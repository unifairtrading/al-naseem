**Status:** Proposed; awaiting user approval. No implementation started under this version.

## Goal
Stabilize the current foundation and verify the baseline before expanding CMS features.

## Proposed tasks
- [ ] Inspect public site and admin code; map current behavior to PRD.
- [ ] Verify current GitHub Actions/deployment status and record actual live baseline.
- [ ] Review Firestore rules against Super Admin and Staff Admin permissions.
- [ ] Fix confirmed blocking issues in public site/admin login/dashboard without unrelated redesign.
- [ ] Ensure Staff Admin edits to permitted business content publish directly, with no second approval step.

## Acceptance criteria
- Public website and /admin work; dashboard data is not exposed before sign-in.
- Role access is enforced by Firestore/server rules, not just hidden UI.
- Staff can edit/publish permitted business data directly.
- Staff cannot grant privileged roles or change security/technical settings.
- Important edits have attributable audit records.
- Umrah and hotel enquiries are distinguishable.
- CI passes and deployment is verified.
